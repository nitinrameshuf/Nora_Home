Todo across the five surfaces

Mockups for review, drawn with the real Almanac tokens — the same glass panes over the same living sky the house already runs. Nothing here is a new visual direction; it is the agreed design placed onto each screen at its true size.

1 · The 24" wall — the real app, at wall scale

The wall is the house's interface to the application, not a passive summary of it. It shows the same board a laptop shows — same columns, same cards, same data. Nothing is a visualization unless someone has navigated to the Reporting tab on purpose.

The only thing that changes is the type scale. The platform already knows which surface it is rendering to, so the wall gets a larger scale throughout: ~1.6× the laptop's, tuned to read from three metres. Same templates, same CSS, one variable.

Visual discipline — learned from the base app's home screen

The platform's own dashboard is the cautionary example. These are its actual failures, and the rules Todo's Reporting page holds itself to so they are not repeated.

What went wrong thereThe rule here
A chart drawn with no data. "Reliability" renders a full axis — 0, 0.2, 0.4, 0.6, 0.8, 1 — with nothing plotted on it. Empty is a sentence, never an axis. If there is no history yet, say so in one line and take up one line of space.
A huge box holding one line. "House vitals" is roughly a quarter of the screen for a single temperature reading. Height follows content. A widget that renders two rows occupies two rows' worth of card.
Ragged alignment. Cards start at different vertical offsets and leave gaps of arbitrary size. One grid, aligned rows, a single gap value. Nothing floats.
Ratio axes. 0 to 1 in increments of 0.2, which nobody reads as a percentage. Percentages are percentages. Durations are durations. Axis labels use the unit a person would say aloud.
Chart furniture. Threshold lines, arrow markers and dotted rules that add marks without adding information. Every mark earns its place. No gridline that a reader would not otherwise miss, no marker that says nothing.
Large cards for absence. "Nothing late. Good." occupying a full-size tile twice over. Good news is small. The quiet state is the compact state.

Two more that hold throughout: numbers that sit in columns use tabular-nums so they do not jitter on refresh, and the accent is spent on one thing per screen — everything else stays in the neutral ink range.

6 · How a widget gets made

Widgets are for the home screen — the personal grid, and whatever the wall shows when it is pointed at /home/. They are not how the Todo app presents itself; the app presents itself as the app.

Todo builds them exactly the way any app does — there is no privileged path. A widget is a Python class that returns data, not HTML; the platform applies the house theme. That is what keeps every chart in the house looking like one system regardless of who wrote it.

Base classYou implementUsed above for
ListWidgetrows() → title, meta, status, url Next up · This week · Done this fortnight
StatWidgetstat() → value, unit, state Today's load · Moved on · Priority 1 · Estimates
ChartWidgetoption() → an ECharts option dict Arriving vs finishing · Finished per day · Last 14 days
TemplateWidgeta template, when the others do not fit the suggestion card

Each declares title, description (what the picker shows), default_size in a 12-column grid, refresh_seconds, and wall_safe — whether it is legible at three metres and calm enough for an always-on screen. The picker respects that flag when someone is arranging the wall.

Every widget above reads from nora_home.todo.analytics — one documented function per metric. The Reporting page calls the same functions, the MCP tools call them, and a future AI layer calls them too. Nothing re-derives a statistic on its own.

Colours are not set by the widget. option() returns structure — series, axes, data — and the house theme colours it. A widget that hardcodes a hex is the one thing that breaks the "all one system" property, and it is why charts look consistent across apps written by different people.
